# 2026 知乎诺奖预测榜

在线页面：https://bretdeng.github.io/nobel-forecast-2026/

## GitHub Pages 与自动更新

各奖项在官方最早公布时间前一小时封榜。最后更新截止时刻（香港时间 UTC+8）：医学 10 月 5 日 16:30、物理 10 月 6 日 16:45、化学 10 月 7 日 16:45、文学 10 月 8 日 18:00、经济学 10 月 12 日 16:45。依据：[诺奖官方公布时间](https://www.nobelprize.org/prizes/about/prize-announcement-dates/)。

最后更新任务提前 15 分钟触发，完成环境准备后等待，在截止前 30 秒开始最后采集，尽量贴近截止点完成。GitHub 调度不保证准点：迟到或跨过截止的采集会跳过，保留之前快照。截止后普通更新、手动同步及单独复核都跳过对应奖项；最后一批截止前完成的采集可以继续完成复核和发布，其他奖项继续更新。所有奖项封榜后不再调用知乎接口或重复发布。

Pages 仅发布 `public/`。推送到 `main` 后自动发布当前榜单，无需启动本地 Node 服务。

GitHub 托管的 Ubuntu Actions 每两小时（UTC 偶数小时的第 17 分钟）调用官方知乎 CLI，抓取五个问题、复核新增/变更摘要、保存数据快照与复核缓存，再发布网页。调度可能延迟；电脑无需保持开机。同步失败时保留此前发布的页面。

在仓库 Settings → Secrets and variables → Actions 中添加 `ZHIHU_ACCESS_SECRET`。只将凭证存为 Actions Secret，不提交到仓库。配置后先手动运行 **Verify Zhihu CLI on GitHub**，通过后运行 **Refresh Nobel Forecast**。缺少凭证时自动更新会失败，静态网页仍可访问。

每次完整同步至少读取五个问题，分页会增加请求次数；新增/变更摘要会消耗直答额度。审核结果提交到仓库，避免相同摘要重复调用 AI。不确定内容保留待人工复核，不自动计票。

GitHub 工作流权限仅用于当前仓库的数据提交与 Pages 发布；Linux CLI 固定使用已校验的官方 0.6.1。详见 `docs/github-actions-cli-verification.md`。

知乎「2026 诺贝尔奖巡礼」活动的延续之作。基于用户指定的五个知乎问题，使用官方 Zhihu CLI 采集回答摘要，并逐条筛选、统一人名与研究方向，生成 benchmark 风格榜单。静态网页无需第三方运行依赖。

## 启动

需要 Node.js 18+ 与 Python 3.10+：

```sh
npm start
```

访问 http://127.0.0.1:2026 。默认仅监听本机，可用 `PORT=3000 npm start` 改端口。

支持：五大奖项切换、候选人与方向榜、中文及英文搜索、票数排序、展开全部预测来源、明确 AI 辅助回答筛选、CSV 导出、JSON 下载、清洗审计和统计方法弹窗。文学奖按作家统计。

## 数据与统计边界

2026-10-04 采集：医学 39、物理 65、化学 16、文学 23、经济学 35，共 178 条服务端摘要（首次采集为 176 条；新增摘要已复核）；接口分页均已读取结束。其中 111 条包含明确、可辨识的正向预测。服务端可能过滤无效或无摘要回答，不能宣称覆盖知乎全部原文。

**当前统计单位是独立回答票数，无法确认独立用户人数。** 官方 `question answers` 返回 ContentToken、Url 和 Summary，没有稳定作者 ID，无法实现严格的按用户去重。未来补充作者 ID 后应按“奖项 + 候选/方向 + 作者 ID”去重，再切换为人数榜；不要把回答数直接命名为预测人数。

同一回答可以给多个候选人或方向投票，每项最多一票。明确的首选、备选及希望获奖名单均计入。票数相同并列，采用竞赛排名（1、1、3）。占比分母为本奖项筛选条件下包含任意有效预测的回答数，多选使占比合计可能超过 100%。

初始人工复核与后续直答 AI 复核均排除否定预测、纯历史回顾、纯转述赔率、明显玩笑、跨奖项内容和无法辨识的截断摘要。**并非关键词命中就计票**：例如“GLP-1 还得往后稍一稍”不计 GLP-1；“大家都提 GLP-1，我选干细胞”只计明确的干细胞预测。方向是对明确成果与人选研究领域的规范化归类，不从方向倒推出摘要里没出现的人名。

对不确定的语境暂不计票，并保留理由。严肃的冷门预测保留；不依据知名度或个人判断移除。明确提到 ChatGPT 或豆包的回答标记为 AI 辅助，默认纳入；没有该标记也不能证明回答未用 AI。

有回答将已获 2025 年化学奖的 MOF 再预测为 2026 年；保留它作为社区预测，并标记事实错误。核查来源：[诺奖官方 2025 化学奖公告](https://www.nobelprize.org/uploads/2025/10/press-chemistryprize2025.pdf)。预测热度不代表获奖概率、官方提名或成果质量。

```sh

```

数据每两小时由服务端自动更新，页面不提供手动同步。官方 CLI 默认路径：

```text

```

其他设备可用 `ZHIHU_CLI_BINARY` 指定官方 CLI 的绝对路径。仅使用 CLI 的钥匙串/环境授权，不向网页发送 Access Secret。可通过官方 skill 的 `scripts/run.sh status` 检查状态。

采集遵循 `Paging.NextOffset`，不以返回条数推算分页；即使一页为空也按分页标记继续。遇到额度、鉴权、超时或分页缺失时停止，保留上次完整快照。服务启动后立即同步一次，之后每两小时自动同步。一次完整同步五个问题可能消耗至少五次接口额度。

同步现在会先让知乎直答 `zhida-fast-1p5` 处理新增/变更摘要，再校验结构、人名/方向别名以及逐字原文引用，通过后计票。`data/reviews.json` 以回答 token 和 SHA-256 绑定审核结果，摘要变更必须重新复核；已有人工审核不会被 AI 覆盖。原始 AI 响应保存在 `data/ai-audit/`，网页审计记录注明复核方式。人工处理不确定内容时，在该文件为摘要填写 `summaryHash`、`reviewed`、`people`、`directions`、`reason`、`warnings`，并设置 `reviewMethod: "human"`，再执行：

```sh
npm run build
```

`python3 scripts/curate.py` 是本次初始快照的人工标注生成器，索引绑定 2026-10-04 的 `data/raw`，用于复现初始审核。刷新后请编辑 `data/reviews.json`，不要用原索引自动标注新内容。

## 文件

- `data/raw/`：首次采集的官方 CLI 原始响应，保留原字段与分页。
- `data/snapshots/`：当前五个问题的完整接口快照与采集时间。
- `data/reviews.json`：按回答 token 保存的审核、人名归一及排除理由。
- `scripts/build.py`：仅聚合经过审核且哈希一致的预测。
- `scripts/fetch.py`：官方 CLI 采集与分页同步。
- `scripts/review.py`：知乎直答复核、证据校验与别名归一。
- `scripts/sync.py`：抓取 → AI 复核 → 构建榜单。
- `data/ai-audit/`：保存原始 AI 响应及其所依据摘要的哈希。
- `public/data.json`：网页可用的榜单、全部摘要、审计信息。
- `public/`：纯 HTML/CSS/JavaScript 界面。
- `server.mjs`：静态服务与每两小时自动同步。

## 直答自动复核

服务每两小时自动运行，也可手动运行 `npm run refresh`：抓取五个问题后，只将新增/变更的摘要发送给知乎直答，每批最多 5 条。默认使用 `zhida-fast-1p5`，调用直答会消耗对应接口额度。它判断作者是否明确预测、提取人名/方向与逐字引用；程序验证 ID、输出结构、实体与引用关系，防止新增不在原文中的名字。AI 判断仍可能有误，不能取代原始来源，网页保留复核理由与方法。

`exclude` 不计票；`uncertain` 或校验失败留待人工复核。AI 调用失败或限流不自动重试，已完成的结果保留，未完成部分继续显示待人工复核。相同摘要的成功结果和不确定/校验失败的记录均缓存，重复同步不重复消耗该条的直答额度。

只处理当前待复核摘要、不重新抓取：

```sh
npm run review
```

明确希望重新让 AI 判断之前不确定的摘要时：

```sh
python3 scripts/review.py --retry-uncertain
npm run build
```

已有人工审核不会自动覆盖。AI 的复核方式与回答是否由作者使用 AI 撰写是两个不同字段，页面的“排除明确 AI 辅助回答”仅筛选作者写作方式，不排除经直答复核的真实社区回答。
